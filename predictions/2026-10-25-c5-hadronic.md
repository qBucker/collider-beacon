# Pre-registration — C5 hadronic extension (multi-jet, b-tagged jet, dimuon)

**Date:** 2026-10-25. **Status:** recorded before any C5 arm is run. The commit
of this file is the timestamp. Predictions and decision rules below are fixed
before the data are read; any later change is a dated amendment appended at the
bottom, never an edit of the text above.

## Purpose

Extend the azimuthal-uniformity audit from the leading-jet channel to hadronic
channels of the same public sample:

- **H1** multi-jet: subleading and third jet azimuths.
- **H2** heavy flavour: leading b-tagged jet azimuth.
- **H3** dimuon system: opposite-sign muon pair azimuth, with the J/psi and
  Upsilon mass windows, plus a storage-precision test on the muon branches and
  a Fourier scan for sector structure.

Scope note carried from the paper: released data carry no entropy. These arms
are audit and pipeline demonstrations (I/V), not live entropy sources.

## Dataset and pass

- Same 67 CMS ZeroBias Run2016G PFNanoAOD files as the phase-0 audit
  (`uris.txt`, sha256 recorded in the analysis note).
- One pass per file over XRootD (`root://eospublic.cern.ch`), with the same
  transport shim used by the phase-0 and E2 sweeps.
- Per-file output: float32 azimuth arrays per arm, dimuon pair masses, event
  counters, manifest with sha256 of the output and of the code.

## Arms (exact selection, fixed here)

Jet kinematics (all jet arms): `|eta| < 2.5`, `pt > 20.0 GeV`; jets ranked by
pt descending; ties resolved by the first occurrence (same rule as the frozen
leading-jet extractor).

- **A (control):** leading jet azimuth.
- **H1a:** second-ranked jet azimuth.
- **H1b:** third-ranked jet azimuth.
- **H2:** highest-pt jet with `Jet_btagDeepFlavB > 0.50`. The cut is a fixed
  threshold; no claim is made that it equals a published working point. A
  secondary threshold of 0.80 is reported as a stability cross-check only.
  The b-tagging input is track and vertex information and is azimuth-blind by
  construction, so the selection is in the G-invariant content class.
- **H3:** the two highest-pt muons with `pt > 4 GeV`, `|eta| < 2.4`,
  `Muon_tightId == 1`; the pair is kept if the charges are opposite. Pair
  azimuth is the azimuth of the vector sum. Pair invariant mass uses the muon
  mass 0.10566 GeV. Mass windows: J/psi `|m - 3.096| < 0.15 GeV`, Upsilon
  `|m - 9.46| < 0.5 GeV`.

## Decision rules

1. Pass = measured value inside the stated band; miss = outside. A miss is
   reported with its diagnosis in the result note, not silently re-banded
   (same practice as E1).
2. If **P0 or P0b misses**, the batch is treated as a pipeline fault: no
   physics claim is made from it until the extractor is fixed and the full
   pass is re-run. The frozen phase-0 numbers are the authority.
3. P5: report the amplitude and its significance. Amplitude above 3 sigma of
   the multinomial null is recorded as a detector-fingerprint candidate;
   otherwise report a 95% upper limit on the amplitude.
4. Entropy certification for an arm requires n >= 10^4 events in that arm;
   below that, only rates, peak positions and shape diagnostics are reported.
5. Per-arm uniformity diagnostics: chi-square p-value and KS p-value at b=8,
   plus the per-file stability split (terciles). These are descriptive, not
   pass/fail gates, except where a band is stated above.

## Gates

- **G1 integrity:** 67/67 files present with manifests and sha256 checksums;
  the file list hash equals the phase-0 list.
- **G2 control:** P0 and P0b hold.
- **G3 determinism:** re-running the analysis on the stored per-file outputs
  reproduces the aggregate JSON bit for bit.

## Amendments

### Amendment 1 — 2026-10-25, before the batch

Engineering feasibility check on `f01` (153,011 events, local copy) found that
this PFNanoAOD product stores very little non-jet content: events with at least
one stored muon 3.8%, photon 1.2%, tau 0.8%, FatJet 0.01%, secondary vertex
13.2%. With `pt > 4 GeV`, `|eta| < 2.4`, `tightId == 1`, 447 muons survive in
153,011 events, giving 2 opposite-sign leading pairs. The dimuon arm (H3)
therefore cannot reach the rule-4 threshold (n >= 10^4) by orders of magnitude.
The muon starvation is itself recorded as a data-product content finding.

H3 is replaced by **H3'**: the secondary-vertex azimuth (`SV_phi`), all stored
secondary vertices, no further selection. This is a heavy-flavour hadronic arm
with an expected rate of roughly 0.13 vertices per event (about 7 x 10^5 in the
full sample). The dimuon arrays remain in the extraction for the record; the
dimuon yield is reported as a limiting measurement with no entropy claim.

Predictions P3, P3b, P4, P5 are replaced by:

| ID | quantity | prediction | basis |
|---|---|---|---|
| P3' | H3' SV azimuth, b=8 pooled h_min | [7.30, 8.00] bit | n about 7 x 10^5, same acceptance argument |
| P4' | SV branch storage precision | two-branch test: full float32 gives no 7.06-bin beat at b=12; truncated gives the beat | branch-wise storage behaviour |
| P5' | Fourier amplitudes k=1..12 in the SV azimuth | no amplitude prediction; 3 sigma decision rule as in rule 3 | exploratory |

Rule 4 still applies per arm. The A-control (P0, P0b), H1 and H2 predictions
are unchanged.
